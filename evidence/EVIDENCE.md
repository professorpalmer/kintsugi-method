# Evidence table for the Kintsugi-method paper (C1-C4)

Status: public copy of the evidence table of the paper (version 1.1). Source cells name a file of this repository where the data is here; "lab record <name>" is a private working log of the project, named so that the row can be traced on request.

## Conventions

- **Pub.** = where the number is public today. `PUBLIC` = in the public Kintsugi-27B repo (path given). `CLEARED` = only
  in this private repo so far, but the owner cleared it for a public version of the paper (2026-11-21).
  `PUBLIC (Inkling release, 11-23)` = an Inkling 2 Mini result, public since the Inkling release (2026-11-23).
- **Sources.** A path is a file of this repository (data/, results/, scripts/); "Kintsugi-27B repository:" points into that public repository; "lab record <name> # <section>" is a private working log, named so that the row can be traced on request.
- **KL.** Mean KL divergence of the next-token distribution against the reference (BF16 for Qwen3.8-27B; the
  dequantized official release for Inkling 2 Mini), on the named golden set, with the quant-challenge scorer
  arithmetic (top-512 + tail). "-7 %" = 7 % lower mean KL than the named comparison arm. Intervals are 95 % paired
  bootstrap intervals over documents unless said otherwise.
- **Golden sets.** Qwen: p1 = 295 public documents, 376,086 scored rows (the build set); p2 = the other 294 documents
  (untouched by map choice); T = every 8th p1 document (74), C = 149 other p1 documents. Inkling: 298 documents
  (even-numbered public documents, re-tokenized), 451,585 scored rows; "copy rows" = 111,777 non-assistant chat rows
  past 1,024 tokens (not scored by the line).
- **Recall gate G2 / R3b.** 24 needle questions (a planted 4-digit code) + 20 exact copies of a code function, at
  117,000 (G2, R3a) or 245,000 (R3b) tokens, thinking off, greedy. Line 24/24 + 20/20.
- **Margin.** For one answer token, log p(right token) minus log p(best wrong token), in nats, teacher-forced on the
  gate's own prompt. Below 0 = greedy decoding writes a wrong token.
- **AppWorld.** test_normal, 168 tasks, temperature 1.0, effort medium, 50 steps, simplified ReAct code agent. "Pooled"
  = two seeds, 336 task-runs. Paired exact two-sided sign test on discordant (task, seed) pairs. Seeds 100 + 101 =
  the seeds on which Qwen bit maps were chosen ("selection seeds"); seeds 102 + 103 = never used for selection;
  seeds 104 + 105 = the paper batch (11-22; never used for a choice; every 12 GB arm through the Kintsugi-27B v1.0.4
  Linux launcher, KINTSUGI_LAYER=0, KINTSUGI_CHAT_TEMPLATE=model). Seeds 106 + 107 went to test_challenge (E1.36, section W2); 108 + 109 to the fresh-seed check of E5.4; Inkling wave 2 used 108-111 (test_normal) and 112 + 113 (test_challenge).
  **Seed clustering (E5.1):** the task-runs of one seed share one random stream, so the exact sign test over task-runs is anti-conservative. Rows written before 11-23 give that task-level p; E5.1 and E5.28 give the design-effect p, the cluster-robust interval and the per-seed signs.
  Inkling arms: seeds 102-105, none used to choose anything for M2 (its map was chosen on the KL golden set). Inkling
  "OURS-medium" = M2 in our engine through the release launcher, effort medium, window 65,536, reasoning budget 20,480.
  "Setup vs setup" = the arms differ in more than the weights (engine, K/V type, reasoning budget); the row says which.
- **Resolution of the sign test.** p < 0.05 needs a split of at least 23 / 10 with 33 discordant pairs, 27 / 13 with 40,
  32 / 17 with 49 (exact two-sided binomial; computed 11-22 for this file). So 336 task-runs resolve a difference of
  about 13-15, and 672 task-runs with about 40 discordant pairs resolve about 14.
- **Model files.**
  - V3a = our exllamav3 fits on the L0xRE-V2 bit layout, 2.4690 bpw on the coded body.
  - V3ac-h32 = V3a rebuilt from public inputs with a Q8_0 head (per 32) = the release file `Kintsugi-27B-12G.gguf`,
    sha256 0510bae8...e48c8a74, 10,546,687,168 B.
  - Inkling M2 = `Inkling-2-Mini-Kintsugi-M2.gguf`, 9,067,638,560 B, sha256 7d93d5e8...0cec.
  - Unsloth Inkling UD-Q2_K_XL: 9,138,715,328 B, sha256 20292e81...1441.
  - Unsloth Qwen3.8-27B UD-Q2_K_XL ("naive"): 9,948,666,784 B, sha256 18f1187f...87e621db4.
  - BF16: ggml-org `Qwen3.8-27B-BF16.gguf`, 53,808,282,240 B, sha256 ee11e869...a9a717bd.
  - LAMQ-8.9 (the OLD file, the only one scored): HF shinmegamiboson/Inkling-2-Mini-LookAtMyQuant-8.9GB at revision 1318b804e687 (2026-11-21; 63-file pack, 8,874,213,027 B). A newer file exists at revision 6a953d2d1787 (2026-11-23); not scored yet (E5.24).
  - Unsloth Inkling UD-Q8_K_XL ("RAW", full precision): 22,867,451,616 B, sha256 dfb04bf3...9a41; every tensor equal
    (max abs diff 0) to our exact dequantization of the official NVFP4 / MXFP8 release (E4.10).
  - Inkling engine builds: ace85a829 (release candidate before the G6 fix), ad657a606 (v1.0 candidate: grammar
    trigger fix, json_object fix, one-slot guard, flash-attention force).
